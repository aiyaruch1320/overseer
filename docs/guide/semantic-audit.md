# วิธีตรวจเชิงความหมายของทั้งโลก

ใช้ก่อนออกแบบระบบพระเจ้า และทุกครั้งที่เพิ่มงานชุดใหญ่ ตัวตรวจโครง (`npm run docs:verify`) จับได้เฉพาะรหัส ตัวเลขในตาราง และลิงก์ ไฟล์นี้กำหนดว่าต้องอ่านอะไรเพิ่ม ใครอ่าน และแก้อย่างไร ผลการตรวจแต่ละรอบบันทึกใน [consistency-checks.md](consistency-checks.md)

ระดับการตรวจ (ตาม [story-seeds.md](story-seeds.md) หัวข้อ 1): โครง · ขอบเขต (อ่านทีละทวีปหรือทีละชุด) · ทั้งโลก (อ่านขนานทุกชุด แล้วให้ผู้อ่านที่ไม่รู้เจตนาอ่านซ้ำ)

## 1. หลักของเกมที่ใช้ตัดสิน

ทุกข้อที่พบต้องชี้ได้ว่าขัดกับหลักข้อไหน ถ้าไม่ขัดหลักใดและไม่ขัดข้อเท็จจริงในไฟล์อื่น ไม่ต้องแก้

| รหัส | หลัก | ตัวอย่างที่ผิด |
| --- | --- | --- |
| P1 | โลกเดินเรื่องเอง ไม่ต้องรอตัวละครหลัก | เหตุการณ์หรือเรื่องของ NPC ที่เกิดได้เฉพาะเมื่อตัวละครหลักลงมือ โดยไม่มีผลเมื่อไม่มีใครอยู่ |
| P2 | เหตุการณ์เปลี่ยนทวีปและประเทศ และปิดเส้นเรื่องที่ผูกกับสิ่งที่หายไป | โหนดที่ต้องไปอัซการ์หลัง DR-01 โดยไม่มีเงื่อนไขปิดหรือรูปหลังเปลี่ยน |
| P3 | NPC ทุกตัวมีชีวิตและนาฬิกาเรื่องของตัวเอง เกิดไม่พร้อมกัน | เรื่องของ NPC มนุษย์อายุ 60 ที่เปิดด้วยเหตุการณ์ยุค 3 ซึ่งเกิดหลังเขาตายแน่นอน |
| P4 | NPC โต้ตอบกันเองและเกิดเรื่องใหม่ได้ | ความสัมพันธ์ที่ฝ่ายหนึ่งอ้างแต่อีกฝ่ายไม่รู้จัก หรือผลของเรื่องหนึ่งไม่ส่งต่อให้อีกเรื่อง |
| P5 | ตัวละครหลักคือ NPC หนึ่งตัวที่ได้พรและคำสาปแบบสุ่มตั้งแต่เกิด ใช้ชีวิตเอง และพระเจ้าช่วยตัดสินใจได้ | ตัวละครหลักได้สิทธิ์ที่ NPC ทั่วไปทำไม่ได้โดยไม่มีพร คำสาป หรือการชี้ทางเป็นเหตุ |
| P6 | การชี้ทางของพระเจ้าเปลี่ยนเส้นเรื่องได้จริง | ทางแยกที่ผลเหมือนกันทุกทาง หรือหน้าต่างพระเจ้าที่ไม่มีผลต่อเรื่อง |
| P7 | เนื้อเรื่องไม่ขัดกันเอง | NPC ตัวเดียวอยู่สองที่ในเวลาเดียวกัน ตายแล้วยังปรากฏ อายุไม่ตรงกันระหว่างไฟล์ เหตุการณ์อ้างผลก่อนเหตุ |
| P8 | เรื่องสมเหตุสมผลกับกติกาของโลก | แวมไพร์ออกแดดโดยไม่มีของกันแดด สไลม์ทำงานในเตาหลอม เผ่าที่บินไม่ได้ข้ามทะเลเมฆเอง |
| P9 | สมดุลของการเกิด การเลือกทาง และความหายากของพร คำสาป อาวุธ | ทางเลือกหนึ่งดีกว่าทุกทางเสมอ พรระดับหายากได้ง่ายกว่าระดับธรรมดา เผ่าหนึ่งมีเรื่องมากกว่าอีกเผ่าหลายเท่า |

## 2. รายการตรวจตามชนิดไฟล์

| ชนิดไฟล์ | ตรวจ |
| --- | --- |
| ประเทศ | ช่อง เผ่า ศาสนา ความสัมพันธ์ตรงกับไฟล์ทวีปและไฟล์ประเทศคู่กรณี · ปมเรื่องอ้างเหตุการณ์ที่เกี่ยวกับประเทศนั้นจริง · ภูมิศาสตร์ตรงกับ `world-map.md` |
| NPC | อายุอยู่ในช่วงอายุขัยของเผ่า (`world-time.md` หัวข้อ 3) · เหตุการณ์ที่ผูกเกิดได้ในช่วงชีวิต (ผล `sim-npc-timeline.mjs`) · ความสัมพันธ์สองทาง · คนเดียวกันไม่อยู่สองประเทศในเวลาเดียวกันโดยไม่มีเหตุ · ทาง ก ข ค ต่างกันจริงและเป็นผลที่เรื่องจบ · เผ่าทำสิ่งที่เผ่านั้นทำได้ |
| เหตุการณ์โลก | เงื่อนไขอ่านสถานะที่มีอยู่จริง (หัวข้อ 0.1) · ยุคที่เปิดตรงกับเหตุผลในเรื่อง · ผลถาวรปิดอะไร และไฟล์ที่ผูกกับสิ่งนั้นปิดตามหรือมีรูปหลังเปลี่ยน · ลูกโซ่ไม่ชี้กลับเป็นวงที่เป็นไปไม่ได้ |
| เหตุการณ์ท้องถิ่น | NPC ที่อ้างอยู่ประเทศนั้นหรือมีเหตุให้ไป · ปีหรือยุคของเหตุการณ์อยู่ในช่วงชีวิตของ NPC · ผลไม่ขัดกับผลในแถว NPC |
| โหนดเส้นเรื่อง | อายุโหนดอยู่ในวัยของเผ่า · ทางเลือกทั้งสามทางเป็นไปได้กับเผ่าและถิ่น · โหนดที่ผูกกับทวีปหรือ NPC ที่อาจหายมีเงื่อนไขปิดหรือทางแทน · ผลของทางเลือกต่างกันจริง · รางวัลมีระดับหายากเหมาะกับความยาก |
| จุดบรรจบ ทายาท พวกพ้อง ศึก NPC ยุคปลาย | ตัวละครที่เกี่ยวข้องยังมีชีวิตและอยู่ที่นั้นในเวลานั้น · ผลส่งต่อให้ไฟล์ที่อ้างถึง · ไม่มีคนเดียวกันมีสองชะตาที่ขัดกัน |
| ระบบและตัวเลข | ระดับหายากเรียงถูก (ธรรมดาได้บ่อยกว่าหายาก) · ไม่มีทางเลือกที่ชนะทุกทาง · โอกาสเกิดและสัดส่วนเผ่าตรงกับเรื่องของโลก |

## 3. สคริปต์ที่ใช้ร่วม

| สคริปต์ | ตอบคำถาม |
| --- | --- |
| `npm run docs:verify` | รหัส ตาราง ลิงก์ (โครง) |
| `node scripts/sim/sim-npc-timeline.mjs` | เรื่องของ NPC ที่ผูกเหตุการณ์ เปิดได้ในช่วงชีวิตของผู้ถือหรือไม่ (P3 P7) |
| `node scripts/sim/sim-npc-density.mjs` | NPC กระจายตามเวลาหรือกระจุกที่ต้นเรื่อง และหนึ่งชีวิตเจอเรื่อง NPC กี่เรื่อง (P3 P4) |
| `node scripts/sim/sim-npc-fate.mjs` | ชะตา NPC ยุคปลายกับอายุขัย |
| `node scripts/sim/sim-world.mjs --why` | เหตุการณ์ที่เกิดยากหรือไม่เกิดเลย (P2) |
| `node scripts/sim/sim-start.mjs 3000 --tables` | ชีวิตแต่ละเผ่าเจออะไร (P9) |
| `docs/_generated/storyline-balance.md` `country-links.md` `event-coverage.md` | สมดุลเรื่องต่อเผ่า ประเทศที่ไปไม่ถึง NPC โดดเดี่ยว (P4 P9) |

## 5. กติกาการแก้

- แก้ให้น้อยที่สุดที่ทำให้ไม่ขัด รักษาหลักใน หัวข้อ 1 และน้ำเสียงคัมภีร์ดิบ (ตาราง รายการ รหัส) ไม่เขียนเป็นนิยาย
- เมื่อสองไฟล์ขัดกัน ไฟล์เจ้าของเรื่อง ([../README.md](../README.md) ตารางไฟล์เจ้าของ) ชนะ ถ้าไม่ชัด ไฟล์ที่ใหม่กว่าชนะ
- รหัสที่อ้างต้องมีอยู่จริง ตัวเลขที่เปลี่ยนในตารางต้องคงกติกาของตาราง (น้ำหนักรวม 100 อายุเรียง)
- ไม่ใส่คำถามหรือโน้ตถึงผู้ใช้ในเอกสาร ไม่แก้ `_generated/` ด้วยมือ
- ระบบพระเจ้ายังไม่ออกแบบ ข้อที่ต้องตัดสินด้วยระบบพระเจ้าบันทึกเป็นจุดฝากไว้ ไม่ออกแบบแทน
- การแก้ของแต่ละรอบบันทึกใน [consistency-checks.md](consistency-checks.md) หัวข้อของรอบนั้น: กฎที่เพิ่มหรือเปลี่ยนเป็นแถวละข้อ การแก้อื่นสรุปแถวละชุด รายละเอียดทีละบรรทัดดูจากประวัติ git
- ผู้อ่านแต่ละชุดไม่แก้ consistency-checks เอง ผู้ประสานรวมบันทึกหลังทุกชุดจบ
