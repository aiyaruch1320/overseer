# ทดสอบกับ DeepSeek จริง

ระบบ: [README.md](README.md) · ค่าใช้จ่าย: [01-cost.md](01-cost.md) · เล่นได้โดยไม่มี LLM: [02-offline.md](02-offline.md) · LLM ที่เปลี่ยนเรื่อง: [04-story.md](04-story.md) · สั่งตัวละคร: [../character/19-wish.md](../character/19-wish.md) · สคริปต์: `scripts/llm/test-deepseek.mjs`

ผู้ใช้ให้ทดสอบด้วยกุญแจ API ที่มีอยู่ (2026-11-01) ไฟล์นี้วัดสามจุดที่ใช้ LLM (`setup` `director` `epitaph`) ว่าคำตอบผ่านตัวตรวจของเกมไหม ภาษาไทยอ่านได้ไหม ใช้โทเคนจริงเท่าไร แคชชนแค่ไหน และช้าแค่ไหน

## 1. วิธีทดสอบ

`node scripts/llm/test-deepseek.mjs [--rounds=2] [--only=epitaph] [--write]` อ่านกุญแจจาก `.env` ส่งตัวอย่างชุดเดียวกันซ้ำตามจำนวนรอบ (รอบแรกแคชเย็น) บันทึกคำตอบทั้งหมดลง `.data/llm-live-test.json` (ไม่อยู่ใน git)

| งาน | ตัวอย่าง | วิธีส่ง | ตัวตรวจ |
| --- | --- | --- | --- |
| `setup` | คำขอแปดแบบ (ภาษาพูด ปฏิเสธ ขอสิ่งที่เป็นไปไม่ได้ ไม่ระบุอะไร) | tool call แบบ strict ที่ปลายทาง `/beta` ทุกช่องเป็น `enum` | รหัสอยู่ในแคตตาล็อก นิสัยไม่เกินสาม หมายเหตุเป็นภาษาไทย |
| `director` | จุดแยกหกจุดพร้อมความทรงจำ และชุดเดิมที่สลับทาง ก กับ ข | tool call แบบ strict | เลือก ก หรือ ข และเหตุผลอยู่ในรายการ เลือกทางเดิมเมื่อสลับตำแหน่ง |
| `epitaph` | ชีวิตสามชีวิต (มนุษย์ ออร์ค เอลฟ์) บันทึกหกถึงเจ็ดข้อ | JSON mode | ช่องครบ อักษรไทยล้วน ไม่มีอักษรละติน หน้าคำปฏิญาณไม่ใช้เสียงของพระเจ้า |
| ลำดับผิด | `setup` สี่คำขอ โดยใส่ข้อมูลไว้หน้ากติกา | เหมือน `setup` | ใช้เทียบแคช |

ทุกคำขอมีรหัสของรอบต่อท้ายข้อมูล เพื่อให้แคชชนได้เฉพาะส่วนหน้าร่วม ไม่ใช่คำขอเดิมทั้งก้อน

## 3. สิ่งที่พบและแก้

| เรื่อง | พบ | แก้ |
| --- | --- | --- |
| strict ไม่บังคับ | แบบที่ให้ช่องเป็น `["string","null"]` คู่กับ `enum` ที่มี `null` ได้คำตอบนอกแคตตาล็อก 4 จาก 8 (ชื่อไทยแทนรหัส สตริงไม่มีเครื่องหมายคำพูด) | ไม่ใช้ `null` ในแบบ ใช้ค่า `none` แทนช่องที่ผู้เล่นไม่ได้ขอ เกมแปลง `none` เป็นว่าง ผล 16 จาก 16 ผ่าน |
