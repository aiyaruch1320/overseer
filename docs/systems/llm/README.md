# LLM ในเกม

ภาพรวม: [../README.md](../README.md) · LLM ที่เปลี่ยนเรื่อง: [04-story.md](04-story.md) · ค่าใช้จ่าย: [01-cost.md](01-cost.md) · เล่นได้โดยไม่มี LLM: [02-offline.md](02-offline.md) · ชื่อที่โลกจำ: [03-naming.md](03-naming.md) · LLM ในระบบพระเจ้า: [../god/05-llm.md](../god/05-llm.md) · ไอเดียเดิม: [../../lore/storylines/llm-ideas.md](../../lore/storylines/llm-ideas.md) · โค้ด: `src/llm/narrator.ts` `server/prompts.ts` `server/api.ts`

ไฟล์นี้บอกว่า LLM มีส่วนในเกมตรงไหน มีผลแค่ไหน ปิดได้อย่างไร ค่าใช้จ่ายอยู่ใน [01-cost.md](01-cost.md)

## 1. รุ่นที่ใช้

ผู้ใช้เลือกแล้ว (2026-11-01): **DeepSeek V4.1 Flash รุ่น 1017** (ชื่อใน API `deepseek-flash` ออก 2026-10-17 ตามบันทึกการเปลี่ยนแปลงของ DeepSeek) โค้ดเดิมใช้ DeepSeek อยู่แล้ว (`server/api.ts` ใช้ `DEEPSEEK_MODEL` ค่าเริ่มต้น `deepseek-flash` และปิดโหมดคิด)

| เรื่อง | ค่า | ผลต่อการออกแบบ |
| --- | --- | --- |
| บริบท | 1 ล้านโทเคน ออกสูงสุด 384K | ไม่เป็นข้อจำกัดของงานในเกม |
| โหมดคิด | เปิดเป็นค่าเริ่มต้น ปิดด้วย `thinking: {type: "disabled"}` | ปิดทุกงาน โทเคนความคิดคิดราคาเป็นโทเคนออก และโหมดคิดไม่สนใจ temperature |
| JSON | `response_format: {type: "json_object"}` ต้องมีคำว่า json และตัวอย่างใน prompt ถ้าไม่ถูกแบบอาจได้ข้อความว่าง | งานที่ตอบหลายช่องใช้ JSON และตรวจซ้ำในโค้ด |
| เลือกจากรายการแบบเข้ม | ผ่าน tool call โหมด strict (ใช้ `enum` ได้ ไม่รองรับ min/max length) | `setup` และ `director` ใช้ tool call strict |
| แคช | อัตโนมัติ เป็นแคชส่วนหน้า สร้างหน่วยแคชที่ท้ายข้อความ user และท้ายคำตอบ ไม่มีอายุแน่นอน (ไม่กี่ชั่วโมงถึงไม่กี่วัน) | ส่วนคงที่อยู่ในข้อความ user แรก ๆ แยกจากข้อมูลที่เปลี่ยน (โค้ดเดิมทำแบบนี้แล้ว) |
| temperature | DeepSeek แนะนำ 1.5 สำหรับงานเขียนสร้างสรรค์ โค้ดเดิมใช้ 1.1 | ร้อยแก้ว 1.3 ถึง 1.5 · งานเลือกค่าและ JSON 0.3 |
| ขีดจำกัด | พร้อมกัน 2,500 คำขอต่อบัญชี | ไม่เป็นข้อจำกัดในช่วงแรก |
| ความเป็นส่วนตัว | ข้อมูลเก็บบนเซิร์ฟเวอร์ในจีนตามนโยบายทั่วไป ยังไม่พบนโยบายเฉพาะ API | ไม่ส่งข้อมูลส่วนตัวของผู้เล่น ส่งเฉพาะสถานะของเกม (ไม่ส่ง `user_id` ซึ่งแยกแคชต่อผู้ใช้และทำให้แคชร่วมไม่ทำงาน) |
| ความพร้อม | uptime ส.ค. ถึง พ.ย. 2026 ราว 99.47% | เกมไม่รอ LLM มีแม่แบบและคลังสำรองเสมอ |

ตัวเลขของรุ่นจากหน้าเอกสาร API และ status ของ DeepSeek ณ 2026-11-01 ([01-cost.md](01-cost.md) หัวข้อ 1)

## 2. ใช้ LLM สามจุด

ผู้ใช้ตัดสินแล้ว (2026-11-01): ใช้ LLM แค่สามจุด ที่เหลือใช้แม่แบบและคลังถ้อยคำ ยังไม่ลงทุนกับ LLM ในงานเขียนถ้อยคำระหว่างชีวิต

| จุด | งาน | ทำอะไร | เปลี่ยนตัวเลขไหม | สวิตช์ | ถ้าไม่มี LLM |
| --- | --- | --- | --- | --- | --- |
| **ก่อนเกิด** | `setup` | แปลคำขอ "อยากได้ตัวละครแบบไหน" เป็นใบคำขอ ([../character/19-wish.md](../character/19-wish.md)) เรียกเฉพาะเมื่อตัวแปลคำพ้องของเกมไม่เข้าใจ | ใช่ เป็นค่าที่ผู้เล่นขอเอง ทุกค่าอยู่ใน `enum` บันทึกกับเมล็ด | `llm_setup` | หน้าเลือกเอง |
| **ระหว่างชีวิต** | `director` | ผู้กำกับที่จุดแยกสำคัญ เลือกหนึ่งในสองทางที่ผู้กำกับตามกติกาจัดอันดับสูงสุด ทางนั้น ×1.5 ([04-story.md](04-story.md) หัวข้อ 3) | ใช่ ภายในทางที่เกมอนุญาต บันทึกลงเซฟ | `llm_director` | ผู้กำกับตามกติกาทำงานต่อ |
| **ตอนจบ** | `epitaph` | สรุปเส้นเรื่องทั้งชีวิตให้ผู้เล่นอ่าน การ์ดตอนจบ จารึก หน้าคำปฏิญาณ ในคำขอเดียว ([04-story.md](04-story.md) หัวข้อ 2) และ `world_legend` เมื่อโลกถึงฉากจบ | ไม่ | `llm_ending` | แม่แบบหลายประโยคประกอบจากบันทึก |

ชื่อของสิ่งที่เกิดระหว่างเล่นมาจากเกมเท่านั้น ([03-naming.md](03-naming.md))

## 3. สวิตช์

ทุกจุดมีสวิตช์ของตัวเอง ค่าเริ่มต้นเปิดทั้งสาม (`llm_director` เปิดตามที่ผู้ใช้ตัดสิน และยังวัดผลตาม [04-story.md](04-story.md) หัวข้อ 3.5 เพื่อตัดสินว่าจะเก็บไว้ไหม)

| สวิตช์ | ค่าเริ่มต้น | ปิดแล้วเป็นอย่างไร |
| --- | --- | --- |
| `llm` (สวิตช์หลัก) | เปิด | ปิดทุกจุด เหมือนไม่มี LLM |
| `llm_setup` | เปิด | สั่งตัวละครด้วยตัวแปลคำพ้องและหน้าเลือกเอง |
| `llm_director` | เปิด | ผู้กำกับตามกติกาอย่างเดียว |
| `llm_ending` | เปิด | สรุป การ์ด และจารึกจากแม่แบบ |

**อ่านจากสองที่** เซิร์ฟเวอร์ (ตัวแปรสภาพแวดล้อม ให้ผู้ดูแลปิดทั้งระบบได้ เช่น เมื่องบหมดหรือผู้ให้บริการมีปัญหา และตอบผ่าน `/api/narrate/status`) และการตั้งค่าของผู้เล่น (ปิดเองได้ทีละจุด) จุดหนึ่งทำงานเมื่อทั้งสองที่เปิด สวิตช์ที่ใช้ตอนเล่นบันทึกลงเซฟ เพื่อรู้ว่าชีวิตนั้นเล่นแบบไหน

## 4. งานที่ยังไม่ทำ

เก็บเป็นไอเดีย ตอนนี้ใช้แม่แบบ (ชั้น 0) และคลังถ้อยคำที่เขียนตอนพัฒนา (ชั้น 1) ตาม [../god/05-llm.md](../god/05-llm.md) หัวข้อ 2 และ [09-library.md](09-library.md)

| กลุ่ม | งาน |
| --- | --- |
| ระบบพระเจ้า | `dream` `dream_wake` `dream_words` `omen` `prayer` `answer_twist` `miracle_day` `chronicle` |
| ระหว่างชีวิต | `chapter` `fate` `flavor` `battle` `npc_voice` `rumor` `homeland_letter` `side_event` `legend` ในโหนด (`hu.e1` `el.a7`) และอาวุธที่ให้รายละเอียดตำนาน (`wl_eridan` `wj_chronicler_r` `wj_bard_r` ใช้แม่แบบของตำนาน) |

`flavor` ในโค้ดเดิมให้ LLM เลือกผลจาก `LLM_FX` เอง เมื่อย้ายไปใช้คลัง เกมสุ่มผลด้วยเมล็ดก่อน แล้วเลือกถ้อยคำจากคลังของผลนั้น

## 5. กติการ่วม

1. **เกมเล่นได้เต็มโดยไม่มี LLM** ทุกจุดมีทางของเกมเอง ([02-offline.md](02-offline.md))
2. เกมตัดสินผล LLM เลือกได้เฉพาะจากรายการที่เกมให้ (`setup` `director`) หรือเรียบเรียงสิ่งที่บันทึกไว้แล้ว (`epitaph`)
3. ข้อมูลที่ส่งเป็นสถานะของเกม ไม่มีข้อมูลส่วนตัวของผู้เล่น ข้อความที่ผู้เล่นพิมพ์ส่งได้เฉพาะ `setup` (ตัดที่ 300 ตัวอักษร)
4. ชื่อคนมาจากชุดชื่อหรือข้อมูลของเกมเท่านั้น
5. ตรวจคำตอบตาม [../god/05-llm.md](../god/05-llm.md) หัวข้อ 7 ไม่ผ่านใช้ทางของเกม
6. เกมไม่รอ `director` ขอล่วงหน้า `epitaph` ขอตั้งแต่ฉากความตายเริ่ม แม่แบบขึ้นก่อนถ้าคำตอบยังไม่มา
7. ค่าที่ LLM ตอบและเปลี่ยนตัวเลขได้บันทึกลงเซฟ เล่นซ้ำจากเซฟใช้ค่าที่บันทึก
