# LLM ในระบบพระเจ้า

ระบบ: [README.md](README.md) · หลักการเดิม: [../../lore/storylines/llm-ideas.md](../../lore/storylines/llm-ideas.md) · โค้ดผู้เล่าเรื่อง: `src/llm/narrator.ts`

ผู้ใช้ตัดสินแล้ว (2026-11-01): LLM เพิ่มเข้ามาเพื่อความหลากหลาย ใช้แค่สามจุด (สั่งตัวละคร ผู้กำกับ สรุปตอนจบ [../llm/README.md](../llm/README.md)) งานในตารางหัวข้อ 3 ของไฟล์นี้ยังไม่ทำ ใช้ชั้น 0 และ 1 ไปก่อน เก็บไว้เป็นไอเดีย ไฟล์นี้จึงมีสองเป้า คือ **ได้ความหลากหลายมากที่สุด** และ **จ่ายต่อชีวิตน้อยที่สุด** โดยไม่ให้ LLM ตัดสินอะไรในโลก

## 1. หลัก

| ข้อ | หลัก |
| --- | --- |
| 1 | **เกมตัดสิน LLM เขียน** ทาง ผล รหัส และตัวเลขมาจากเกมเสมอ (Hidden Door: LLM ไม่รู้กติกาของเกม เกมต้องคุมราง) |
| 2 | **LLM เลือกได้เฉพาะจากเมนูที่เกมให้** ถ้า LLM เลือกอะไร (รายละเอียด น้ำเสียง ชื่อ) ต้องเป็นค่าใน `enum` ของแบบข้อมูลออก |
| 3 | **สามชั้นของถ้อยคำ** ทุกงานมีแม่แบบ (ชั้น 0) และคลังที่สร้างตอนพัฒนา (ชั้น 1) LLM ระหว่างเล่น (ชั้น 2) ใช้เฉพาะเมื่อข้อมูลเฉพาะตัวเกินกว่าที่คลังครอบได้ |
| 4 | **เกมไม่รอ** ขอล่วงหน้าตอนจังหวะเงียบ ถ้ายังไม่ได้ใช้ชั้นที่ต่ำกว่า |
| 5 | **ชื่อมาจากเกมเท่านั้น** ไม่ใช้ LLM ตั้งชื่อระหว่างเล่น ([../llm/03-naming.md](../llm/03-naming.md)) บทบาทที่เปลี่ยนเรื่องได้อยู่ใน [../llm/04-story.md](../llm/04-story.md) |
| 6 | **ไม่มี LLM ก็เล่นได้เต็ม** เชื่อมต่อไม่ได้หรือเครดิตหมด เกมใช้ชั้น 0 และ 1 ผลเหมือนเดิมทุกตัวเลข ([../llm/02-offline.md](../llm/02-offline.md)) |
| 7 | **กุญแจ API อยู่ที่เซิร์ฟเวอร์** เบราว์เซอร์ส่งชื่องานกับข้อมูลสั้นเท่านั้น (ตามโค้ดเดิม) |

## 2. สามชั้นของถ้อยคำ

| ชั้น | คืออะไร | ราคาระหว่างเล่น | ความหลากหลาย |
| --- | --- | --- | --- |
| 0 แม่แบบ | ประโยคมีช่องว่าง เขียนมือหรือมีอยู่ในโค้ด | 0 | ต่ำ |
| 1 คลัง | ถ้อยคำหลายแบบต่อชุดสถานะ (ชนิดงาน × ชนิดเหตุการณ์ × น้ำเสียง × ช่อง) สร้างตอนพัฒนาด้วย LLM รุ่นใหญ่ผ่าน batch ตรวจด้วยตัวตรวจในข้อ 7 สุ่มให้คนอ่าน 5% แล้วส่งไปกับเกมเป็น JSON เลือกด้วยเมล็ดของโลก | 0 | สูง (เป้า 20 แบบต่อชุดสถานะ) |
| 2 สดระหว่างเล่น | LLM รุ่นเล็กเขียนจากข้อมูลเฉพาะของชีวิตนี้ | ต่ำ | สูงสุด เฉพาะตัว |

**กติกาเลือกชั้น** ใช้ชั้นสูงสุดที่เปิดอยู่ (ตั้งค่าได้) ถ้าชั้น 2 ไม่ตอบทันหรือไม่ผ่านตัวตรวจ ใช้ชั้น 1 ถ้าคลังไม่มีชุดสถานะนั้น ใช้ชั้น 0

**ราคาของคลัง** ตัวอย่าง 10,000 แบบ × 100 โทเคนไทย = 1 ล้านโทเคนออก ราว 0.25 ดอลลาร์บน Haiku 5.5 แบบ batch หรือราว 5 ดอลลาร์บน Sonnet 5.5 แบบ batch ครั้งเดียวต่อรุ่นของเกม (ราคาจากหน้าราคาของผู้ให้บริการ ณ 2026-11-01)

| `npc_voice` | NPC พูดถึงพระเจ้า | 1 (2 เฉพาะ NPC ที่เป็นพวกพ้อง) | | NPC บทบาท ความรู้สึกจากแกนสี่แกน | 1 ถึง 2 ประโยค |

## 4. LLM เพิ่มความเป็นไปได้อย่างไร โดยไม่แตะกติกา

| ทาง | ทำอย่างไร | ตัวอย่าง |
| --- | --- | --- |
| เลือกรายละเอียดจากเมนู | เกมเสนอรายละเอียดสามแบบที่ไม่เปลี่ยนตัวเลข (จุดที่ดาวตก ใครเห็นก่อน สีของแสง ของที่ผู้รอดถือออกมา) LLM เลือกหนึ่งตามที่เข้ากับเรื่อง แล้วเล่า | ดาวตกใส่ตลาดหรือใส่วิหาร เรื่องของผู้รอดต่างกัน |
| น้ำเสียงตามผู้พูด | ถ้อยคำเดียวกันเปลี่ยนตามเผ่า ศาสนา และความรู้สึกของผู้พูด | ผู้ปรนนิบัติมังกรเล่าดาวตกเป็นการลงโทษ ผู้ไร้ศาสนาเล่าเป็นหินจากฟ้า |
| ความทรงจำที่อ้างกลับ | ข้อมูลเข้ามีสองถึงสามบรรทัดจากพงศาวดาร LLM โยงถึงสิ่งที่เคยเกิดได้ (Hades: เกมรู้ว่าเกิดอะไรมาแล้ว) | ตัวละครพูดถึงความฝันที่เคยปฏิเสธ |
| ข่าวลือหลายแบบของความจริงเดียว | เกมรู้ความจริง LLM เขียนข่าวลือที่ถูกบางส่วนตามระดับความน่าเชื่อที่เกมกำหนด | ข่าวของในที่ลับมีทั้งชี้ถูกทวีปและชี้ผิดเมือง |

ทุกทางข้างบนไม่เปลี่ยนตัวแปรของโลก ทางที่เปลี่ยนตัวแปรของโลกมาจากตารางของเกมเท่านั้น (หีบ ความฝัน ปาฏิหาริย์ เสกตามใจ)

## 5. ทำให้ถูก

ค่าต่อชีวิตขึ้นกับ **จำนวนคำขอ ความยาวของคำตอบ และโทเคนความคิด** มากกว่ารุ่นที่เลือก ผลวิจัยพบว่าโทเคนภาษาไทยที่ออกคือส่วนใหญ่ของค่าใช้จ่าย

| เทคนิค | กติกา |
| --- | --- |
| รุ่นเล็ก | งานชั้น 2 ใช้ DeepSeek V4.1 Flash (`deepseek-flash`) ตามที่ผู้ใช้เลือก โค้ดฝั่งเซิร์ฟเวอร์ใช้รูปแบบ OpenAI จึงเปลี่ยนผู้ให้บริการได้ถ้าจำเป็น |
| ปิดการคิด | ตั้งระดับความคิดต่ำสุดหรือปิด โทเคนความคิดคิดราคาเป็นโทเคนออก |
| คำสั่งเป็นอังกฤษ คำตอบเป็นไทย | คำสั่ง ข้อเท็จจริงของโลก และแบบข้อมูลเป็นภาษาอังกฤษ (โทเคนน้อยกว่า) ขอเฉพาะคำตอบเป็นไทย |
| แคชส่วนหน้าของคำสั่ง | ส่วนคงที่ (กติกาการเขียน น้ำเสียงของโลก แบบข้อมูล ตัวอย่าง) อยู่ในข้อความ user แรก ๆ เพราะ DeepSeek สร้างหน่วยแคชที่ท้ายข้อความ user ข้อมูลของชีวิตอยู่ข้อความสุดท้าย ([../llm/01-cost.md](../llm/01-cost.md) หัวข้อ 3) |
| แบบข้อมูลออกบังคับ | `response_format` แบบ JSON สำหรับงานหลายช่อง และ tool call โหมด strict ที่มี `enum` สำหรับงานที่ต้องเลือกค่า ลดคำตอบเสียและการขอซ้ำ |
| รวมคำขอ | สามทางของความฝันในคำขอเดียว ลางและข่าวลือของทั้งปีชีวิตในคำขอเดียว ห้าจังหวะของวันเกิดเหตุในคำขอเดียว |
| ขอล่วงหน้า | ตอนจังหวะเงียบ ขอข้อความของสิ่งที่น่าจะเกิดถัดไปหนึ่งถึงสองอย่าง (ความฝันของโหนดถัดไป คำอธิษฐานที่น่าจะเกิด) ถ้าไม่ได้ใช้ เก็บเข้าแคช |
| แคชตรงตัว | กุญแจ = แฮชของ (งาน รุ่นของแบบข้อมูล รุ่นของคำสั่ง ภาษา รุ่นของข้อเท็จจริงโลก ช่องสถานะ กลุ่มเมล็ด) เก็บในเครื่องผู้เล่น |
| แคชร่วมระหว่างผู้เล่น | เซิร์ฟเวอร์เก็บคำตอบตามกุญแจเดียวกัน เพราะไวยากรณ์ของเกมปิด กุญแจจึงชนกันบ่อย ผู้เล่นที่ได้ชุดสถานะเดียวกันได้คำตอบที่มีอยู่แล้ว (ไม่ส่งข้อมูลส่วนตัว มีแต่ช่องสถานะ) |
| ตัดความยาว | กำหนดจำนวนโทเคนออกสูงสุดต่องาน (ความฝันทั้งชุดไม่เกินราว 300 โทเคน) |
| สร้างคลังนอกช่วงเร่งด่วน | DeepSeek ไม่มี batch แต่นอกช่วงเร่งด่วนลดครึ่งราคา สร้างคลังชั้น 1 ตอนกลางคืนเวลาไทยหรือวันหยุด สิบชิ้นต่อคำขอ |
| วัดก่อนตั้งงบ | วัดแล้วด้วย tokenizer ของ V4.1 Flash: ไทยราว 2.2 ตัวอักษรต่อโทเคน ([../llm/01-cost.md](../llm/01-cost.md) หัวข้อ 2) |

**งบอ่อน** ยังไม่มีเพดานราคา ระบบใช้งบอ่อนต่อชีวิตเป็นโทเคน ตั้งค่าได้ เมื่อใช้ถึงงบ งานที่สำคัญน้อยลงไปใช้ชั้น 1 ตามลำดับนี้ (ตัดก่อน → ตัดหลัง): `npc_voice` → `rumor` → `omen` → `prayer` → `dream_wake` → `chronicle` → `answer_twist` → `vow_page` → `miracle_day` → `dream` บันทึกโทเคนที่ใช้จริงทุกคำขอ เพื่อหาเพดานจริงจากการทดสอบ

## 6. ประมาณค่าต่อชีวิต

ผู้ใช้เลือกรุ่น DeepSeek V4.1 Flash รุ่น 1017 (2026-11-01) ตัวเลขทั้งหมดของทุกงานในเกม (รวมงานนอกระบบพระเจ้า) อยู่ใน [../llm/01-cost.md](../llm/01-cost.md) คำนวณด้วย `node scripts/sim/sim-llm-cost.mjs` ผู้ใช้ตัดสิน (2026-11-01) ให้ใช้ LLM แค่สามจุด (สั่งตัวละคร ผู้กำกับ สรุปตอนจบ) ([../llm/README.md](../llm/README.md) หัวข้อ 2) งานของระบบพระเจ้าในไฟล์นี้ (`dream` `omen` `prayer` ฯลฯ) **ยังไม่ทำ** ใช้แม่แบบและคลังไปก่อน ค่าเริ่มต้นราว 0.0015 ดอลลาร์ต่อชีวิต

## 7. ตรวจคำตอบ

| ตรวจ | ไม่ผ่านแล้ว |
| --- | --- |
| เป็น JSON ตามแบบ ช่องครบ ค่าที่เลือกอยู่ใน `enum` | ขอใหม่หนึ่งครั้ง แล้วใช้ชั้นที่ต่ำกว่า |
| ความยาวตามเพดาน (ประโยค ตัวอักษร) | ตัดท้าย ถ้ายาวเกินสองเท่าใช้ชั้นที่ต่ำกว่า |
| เป็นอักษรไทยเป็นหลัก | ใช้ชั้นที่ต่ำกว่า |
| ชื่อเฉพาะทุกชื่ออยู่ใน `allowed_names` หรือชื่อสถานที่ของประเทศที่ส่ง | ใช้ชั้นที่ต่ำกว่าสำหรับชิ้นนั้น |
| ไม่มีรหัส ตัวเลข หรือผลที่ไม่ได้ส่ง | ใช้ชั้นที่ต่ำกว่าสำหรับชิ้นนั้น |
| เงาของผลไม่บอกผลตรง | ใช้เงาของสัญลักษณ์จากชั้น 0 |
| ผ่านตัวกรองเนื้อหาของเซิร์ฟเวอร์ | ใช้ชั้นที่ต่ำกว่า |

บันทึกทุกคำตอบพร้อมแฮชของสถานะ ใช้ทำคลังรุ่นถัดไปและทดสอบถอยหลัง

## 9. สิ่งที่ LLM ห้ามทำ

- ตัดสินว่าตัวละครทำตามความฝันไหม หรือผลของการทอยใด ๆ
- เลือกสามทางของความฝันหรือของในหีบ
- เลือกเป้าหมาย ผล หรือเงาสะท้อนของปาฏิหาริย์และการเสกตามใจ
- สร้างเหตุการณ์ที่เปลี่ยนสถานะโลก
- พูดแทนพระเจ้า พระเจ้าไม่มีเสียงในเกม ผู้เล่นคือพระเจ้า ข้อความที่ตัวละครได้ยินคือสิ่งที่ตัวละครเข้าใจ

## 10. ขั้นต่อไปที่ต้องวัด

1. นับโทเคนภาษาไทยจริง (ทำแล้วกับ tokenizer ของ V4.1 Flash) และเทียบกับ `usage` ของคำขอจริง
2. วัดเวลาตอบและอัตราไม่ผ่านตัวตรวจของแต่ละรุ่น
3. ทำตัวตรวจและชั้น 0 ให้ครบก่อนมีชั้นแคช
4. สร้างคลังนำร่องราว 500 แบบ วัดอัตราชนของแคช
